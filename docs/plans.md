### 気づき（テストリストに入れるかはユーザーが判断）

- 起動時に253ファイル（約530MB）を同期でハッシュしている。体感で遅ければ Task でバックグラウンド化する
- クリック音のようなスパイクが長い無音を分断すると、文の境界が消える。今の教材には見つからなかったが、必要になったら「最小有音長」パラメータ（例: 100ms未満の有音を無音に吸収）を足す
- mp3 のエンコーダ遅延: javasound-mp3 は LAME タグを読まないので、デコード結果の先頭に約25ms、末尾にパディングの余分が残る（実測: 10.5秒の音声で2358サンプル = 約53ms）。再生は JavaFX Media で行うので、検出側と再生側で遅延の扱いが違う可能性がある。ターンのクリック再生で再生位置が数十ms ずれていないかを確認する
- 音声フォルダを変えると、前のフォルダのファイルの segment と unit の行（指紋がキー）はどこからも参照されない孤児として残る。害は無く量も小さいが、掃除する処理を足す余地はある

# 音声フォルダ

- [x] 音声フォルダを自由に1つ登録する（ストーリーマップ）
  - 現状: App に固定のパス（AUDIO_FOLDER）があり、起動時に UnitLoader でそのフォルダを走査して ViewModel に渡している。unitPane の header にそのパスを表示している。フォルダはどこにも保存していない
  - 決定（ユーザー）
    - 設定ウィンドウはモーダルダイアログ。起動時に音声フォルダが未登録なら、そのダイアログが開く
    - ダイアログの中身: ラベル「音声ファイルのあるフォルダを追加してください」、ボタン「追加」。押すとフォルダ選択ダイアログ（DirectoryChooser）
    - フォルダを選ぶと、「ドリル名」フィールドにフォルダ名、その下の「ドリルの場所」ラベルにフォルダのパスが入る。ドリル名は変更可能で空欄不可
    - フォルダが選ばれていて、ドリル名が空でなければ「保存」を押せる。押すと保存して走査を始める（走査は同期）
    - 保存先は DB（今後フォルダが増えるので、テーブルにする）
  - 設計案（残りは提案どおり）
    - ドメイン: 登録したフォルダは AudioFolder（name, path）。name は空欄不可、path は非 null。UI の文言は「ドリル名」「ドリルの場所」だが、コード上は Drill（ユニット内の5ドリル）と混同しないよう AudioFolder と呼ぶ
    - DB: audio_folder テーブル（id、name、path、登録順）。リポジトリ AudioFolderRepository は保存と一覧の読み出し。いまは1つだけ使い、2つ目以降は次のストーリー
    - ダイアログの ViewModel（AudioFolderSettingsViewModel）: 選んだフォルダ、ドリル名、パスの表示、保存可否、保存。フォルダ選択ダイアログは差し替え可能な関数として渡し、テストでは固定のパスを返す
    - 本体: App の固定パス AUDIO_FOLDER をなくす。起動時に登録済みなら走査して表示、未登録ならダイアログを開き、保存後に走査して表示。unitPane の header にはフォルダのパスではなくドリル名を表示し、その横に設定ボタン（SETTINGS アイコン）を置いて後からもダイアログを開ける。フォルダを変えたら走査し直してユニット一覧を入れ替え、再生は停止、選択は外す
  - テストリスト（案。ユーザーが確認）
    - [x] AudioFolder: 名前が空欄（空文字か空白だけ）なら IllegalArgumentException。path が null なら NullPointerException
    - [x] SqliteAudioFolderRepository: 保存した音声フォルダを一覧として読み出せる。何も無ければ空の一覧
    - [x] SqliteAudioFolderRepository: 同じフォルダをもう一度保存しても一覧は1件のまま（今は1つだけ登録できる。名前の変更は上書き）
    - [x] SqliteAudioFolderRepository: 別のパスのフォルダを保存すると、前のフォルダは置き換わって一覧は1件のまま（登録できるフォルダは1つだけ。実機で、保存後に設定を開くと起動時のフォルダが出る不具合の切り分け）
    - [x] AudioFolderSettingsViewModel: 初期状態はフォルダ未選択、ドリル名は空、パスの表示は空、保存不可
    - [x] AudioFolderSettingsViewModel: 登録済みのフォルダがあれば、開いたときにそのドリル名と場所が既定値として入っていて、そのまま保存できる（ユーザー追加）
    - [x] AudioFolderSettingsViewModel: フォルダを選ぶと、ドリル名にフォルダ名、パスの表示にフォルダのパスが入り、保存可能になる
    - [x] AudioFolderSettingsViewModel: ドリル名を空にすると保存不可になり、入れ直すと保存可能に戻る
    - [x] AudioFolderSettingsViewModel: 保存すると、ドリル名とパスの AudioFolder がリポジトリに保存され、保存したフォルダを呼び出し元に知らせる
    - [x] AudioFolderSettingsView: ラベルの文言、「追加」ボタン、ドリル名フィールド、パスのラベル、「保存」ボタンがあり、保存ボタンは ViewModel の保存可否に従って disabled になる
    - [x] AudioFolderSettingsView: 「追加」を押すとフォルダ選択（差し替えた関数）が呼ばれ、選んだフォルダが ViewModel に入る
    - [x] UnitViewModel: 音声フォルダとユニット一覧を入れ替えられる。入れ替えると再生が停止し、選択が外れ、header の表示がそのドリル名になる（パスの表示はやめる）
    - [x] UnitView: unitPane の header に設定ボタン（SETTINGS アイコン）があり、押すと設定ダイアログが開く
    - [x] 起動: 登録済みのフォルダがあればそれを走査して表示し、ダイアログは開かない。無ければモーダルダイアログが開き、保存すると走査して表示する（App の固定パスをなくす）
