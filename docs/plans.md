# 現在の再生ドリルをリストで確認できる

- [ ] ADR-001を参照して、無音区間を検出する。検出結果はセグメントのリスト。セグメントは区間長と有音・無音の区別を持つrecord
  - [ ] PCMをパラメータで検出すると、セグメントのリストが得られる。内部でPCMをウィンドウ幅ごとに区切り、しきい値未満のウィンドウを無音、無音が最小無音長以上続く区間を無音セグメント、それ以外を有音セグメントとする。セグメントの区間長の合計はPCMの長さに一致する
    - インタフェース案: service の SilenceDetector。コンストラクタで SilenceDetectionParameters を受け取り、List<Segment> detect(PcmAudio pcm) を持つ
    - 合成PCMのケース（テスト内で生成。44.1kHz、モノラル、有音は振幅16384、無音はゼロ）
      - [ ] 全体が有音のPCM（3秒）は、区間長3秒の有音セグメント1つになる。最も単純な形で、セグメントが返ることを確かめる
      - [ ] 有音1秒・無音3秒・有音1秒のPCMは、有音1秒・無音3秒・有音1秒の3セグメントになる。最小無音長以上の無音が区切りになり、区間長が位置と一致することを確かめる
      - [ ] 有音1秒・無音0.5秒・有音1秒のPCMは、区間長2.5秒の有音セグメント1つになる。最小無音長未満の無音（文中のポーズ）は有音に含まれることを確かめる
      - [ ] 無音がちょうど最小無音長（1秒）のPCMは、その無音が無音セグメントになる。最小無音長の境界値が「以上」であることを確かめる
      - [ ] 無音3秒・有音1秒のPCMは、先頭が無音セグメントになる。無音で始まるファイルを扱えることを確かめる（要検討: 「冒頭の無音は無視」をどこで実現するかで、このケースの期待値が変わる）
      - [ ] 有音1秒・無音3秒のPCMは、末尾が無音セグメントになる。無音で終わるファイルを扱えることを確かめる
      - [ ] PCMの長さがウィンドウ幅で割り切れないとき（例: 1.01秒）も、セグメントの区間長の合計はPCMの長さに一致する。端数のサンプルが失われないことを確かめる。端数は短いウィンドウとして独立させ、他と同じくRMSで判定する
      - [ ] 音量がしきい値（-45 dBFS）ちょうどのウィンドウは有音、それより小さい（例: -50 dBFS）ウィンドウは無音として扱う。しきい値の境界値が「未満」であることを確かめる
      - [ ] 全体が無音のPCM（3秒）は、区間長3秒の無音セグメント1つになる
      - [ ] サンプルが空のPCMは検出できず、IllegalArgumentException になる。Loudness.dbfsOf と同じ契約
    - テスト用音声のケース（src/test/resources/audio、既定パラメータ）
      - [ ] WAVを検出すると、有音1.0秒・無音3.0秒・有音2.5秒・無音3.0秒・有音1.0秒の5セグメントになる。0.5秒の文中ポーズが有音に吸収されることと、実ファイルで設計どおりに動くことを確かめる。区間長の誤差はウィンドウ幅（20ms）以内
      - [ ] mp3を検出しても、WAVと同じ5セグメントになる。エンコーダ遅延（約53ms）で先頭の有音が少し長くなるので、許容幅は0.1秒とする。mp3の符号化ノイズが無音判定を妨げないことを確かめる
  - [x] ウィンドウ幅・しきい値・最小無音長はパラメータとして外に出す（SilenceDetectionParameters(windowWidth, silenceThresholdDbfs, minSilenceDuration)、DEFAULT 定数）
    - 前提（実測）: 文の間の無音は natural 3秒以上、slow 2秒以上、導入ユニット 1.2秒以上。文中のポーズは0.5秒未満。冒頭に約0.7秒の無音
