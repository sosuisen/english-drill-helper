# ADR 003: 無音区間検出のパラメータをシャドーイング用の無音を前提に決める

## Status

Accepted（2026-09-05 改訂: 実際の教材の測定に基づき、無音の長さの前提と最小無音長を変更した）

## Context

ADR-001 は、無音区間の検出を純粋Javaで実装すると決めた。PCMを一定時間のウィンドウに区切り、ウィンドウごとのRMSをdBFSに換算し、しきい値未満が最小無音長以上続く区間を区切りとする方式である。ただし、ウィンドウ幅・しきい値・最小無音長の具体的な値は決めず、実装時に教材音声で調整するとした。

このアプリが対象とする教材は『英語のハノン』のようなドリル音声である。1つのファイルに多数の文が収められ、文と文の間の無音は、学習者がシャドーイングするために意図的に設けられている。当初は、この無音は3秒以上あると見込んでいた。2026年9月5日に実際の教材（253ファイルのうち8ファイル）をffmpegのsilencedetect（しきい値 -45 dBFS）で測ったところ、文の間の無音は種別によって異なった。natural版（Unit 19.4）は3.0秒以上、slow版（Unit 3.3〜19.3）は2.0秒以上で2.08秒のような値もあり、導入ユニット（Unit 0.10）は1.2〜1.9秒だった。全ファイルの冒頭に約0.7秒の無音がある。一方、文中のポーズは0.5秒未満で、0.5秒以上のものは1つも見つからなかった。クリック音のようなスパイクで長い無音が分断される箇所もなかった。

ADR-001 の技術検証は合成音で行い、0.5秒と0.7秒の無音を検出し、0.2秒の無音を無視した。この設定は教材の性質を反映していない。

検出した境界は、文単位の再生の開始位置として使う。文頭が欠けると練習に支障が出るため、文頭の位置精度は重要である。ADR-001 は、mp3のエンコーダ遅延による約50msの位置ずれを許容している。

用語を確認しておく。RMS（Root Mean Square）は、ウィンドウ内の各サンプルを二乗して平均し、平方根を取った値である。波形には正負があるが、二乗と平方根によって正の値に正規化される。これにより区間の平均的な音量を表し、瞬間的なノイズに強い。dBFS（decibels relative to Full Scale）は、デジタル音声の最大振幅（16bit PCMでは32767）を0とし、そこから何デシベル小さいかを表す単位である。20 × log10(RMS / 32767) で求め、常に0以下になる。6dB下がるごとに振幅が半分、20dB下がるごとに振幅が10分の1になる。デジタル無音ではRMSが0となり、dBFSは負の無限大になる。フルスケールという明確な基準を持つ点で、基準のない単なるdBや、空気中の音の大きさを表すdB SPLとは異なる。ファイルの中の数値だけで決まり、再生時の音量には影響されない。

## Decision

無音区間検出の初期パラメータを次のとおり定める。

| パラメータ | 値 |
|---|---|
| ウィンドウ幅 | 20ms |
| しきい値 | -45 dBFS |
| 最小無音長 | 1秒 |

ウィンドウは重ねず、隣接させる。ウィンドウごとに全チャンネルのサンプルをまとめてRMSを求め、dBFSに換算する。デジタル無音のdBFSは負の無限大であり、しきい値との比較でそのまま無音と判定する。

3つのパラメータは検出クラスの外から与える値とし、コードに埋め込まない。上の値は初期値であり、実際の教材音声で調整してよい。調整は ADR-001 の方針の範囲内であり、この ADR の改訂は不要とする。

## Alternatives

### 代替案1: ウィンドウ幅を 10ms にする

境界の位置精度は上がる。しかし男性の声の基本周波数は100Hz前後で1周期が約10msあり、ウィンドウが1周期の途中で切れてRMSが揺れ、無音判定がちらつく。20msなら2周期以上を含み安定するため採用しない。

### 代替案2: ウィンドウ幅を 50〜100ms にする

RMSはさらに安定する。無音が3秒以上あるなら、無音の検出自体は粗いウィンドウでも成功する。しかしウィンドウ幅は文頭の位置誤差になり、文頭が欠ける恐れがある。処理量は20msでも10分のファイルで3万ウィンドウ程度であり問題にならないため採用しない。

### 代替案3: 最小無音長を 0.3〜0.5秒 にする

技術検証の設定に近い値である。測定では文中のポーズが最大0.46秒だったので、0.5秒なら誤検出しない可能性はある。しかし文中のポーズとの余裕がほとんどなく、少し長い息継ぎで文が割れる。文の間の無音は最短でも1.2秒なので、短い値にする利点がないため採用しない。

### 代替案4: 最小無音長を 2秒または3秒にする

当初は2秒を採用していた。natural版だけなら3秒でも動く。しかしslow版には2.08秒の無音があり、2秒ではぎりぎりで検出漏れの危険がある。導入ユニットの1.2〜1.9秒の無音は、2秒でも3秒でもすべて見逃す。1秒なら、文中のポーズ（0.5秒未満）と文の間の無音（1.2秒以上）の両側に余裕があるため、1秒を採用する。

### 代替案5: RMSではなくピーク値で判定する

計算が単純である。しかしピーク値は1サンプルのクリック音やノイズで跳ね上がり、無音判定が不安定になる。RMSは区間の平均的なエネルギーで、人が感じる音量にも近いため、RMSを採用する。

### 代替案6: しきい値をdBFSではなくRMSの生の値で指定する

換算が不要で実装は最も単純である。しかし人の耳は音量を対数的に感じるため、線形の値ではしきい値の意味が直感的に分からない。話し声（RMS 3000〜10000）から符号化ノイズ（RMS 10〜30）まで値の幅が広く、調整しにくい。また、ffmpegのsilencedetectをはじめ音声処理のツールや文献はdBFSでしきい値を表すので、dBFSにしておけば他のツールで測った値をそのまま持ち込める。以上の理由でdBFSを採用する。

## Confidence Level

最小無音長についての確信度は高い。8ファイルの測定に基づいており、文中のポーズ（0.5秒未満）と文の間の無音（1.2秒以上）の間に置いてある。ただし測定していないファイルに0.5〜1秒の文中ポーズや1秒未満の文の間の無音があれば、境界を間違える。

ウィンドウ幅についての確信度は高い。音声処理の分野で標準的な値であり、位置精度と安定性の両方を満たす。

しきい値についての確信度は中程度。教材の意図的な無音はほぼデジタル無音と見込むが、実際のノイズフロアはまだ測っていない。-45 dBFS はmp3の符号化ノイズ（-60 dBFS 前後）を吸収する余裕を持たせた値である。

次の場合にこの決定を見直す。文の間の無音が1秒未満の教材や、文中のポーズが1秒以上ある教材を扱うとき。クリック音などのスパイクで無音が分断される教材を扱うとき（最小有音長のパラメータを足す）。録音にノイズが多く、-45 dBFS で無音を検出できない教材を扱うとき。文頭が欠ける事例が実際の練習で見つかったとき。

## Consequences

良い結果。文中のポーズで文が割れない。境界の誤差は最大20msで、ADR-001 が許容した50msより小さい。ウィンドウを重ねないので実装が単純になる。パラメータが外にあるので、教材に合わせて調整できる。

悪い結果。文の間の無音が1秒未満の教材では、複数の文が1つのドリルにまとまる。文中のポーズが1秒以上ある教材では、1つの文が割れる。テスト用の音声は、技術検証のもの（0.5秒と0.7秒の無音）をそのまま使えず、3秒の無音と、無視されるべき0.5秒程度の文中ポーズを入れて作り直す。

中立な結果。デジタル無音のdBFSは負の無限大になる。しきい値との比較は正しく動くが、値を表示や計算に使う場面では扱いに注意する。
