# ADR 004: ドリルの区切りを教材の構造（Key sentence の対と Cue）から決める

## Status

Proposed

## Context

ストーリーマップ（docs/storymap.md）では、学習者はユニットのドリルを一覧で確認し、ドリルをクリックして冒頭から再生する。英語のハノンでは、1ユニットは5つのドリルからなり、各ドリルは録音音声と学習者が交互に話すターンの並びである。アプリは無音区間検出（ADR 001、ADR 003）で得たセグメント列を、ドリルとターンに組み立てなければならない。

最初は「1ユニット5ドリル、ターン数はドリルごとに等しい」と仮定し、ターン数を5で割る方式を実装した。2026年9月5日に実際の教材253ファイルを ffmpeg の silencedetect（-45 dBFS、最小無音長1秒）で測ったところ、この仮定は次の点で崩れた。

教材の実際の構造は、有音の長さの並びから次のように読み取れた。通常のユニットでは、各ドリルは「Key sentence × 2 → (Cue → Answer × 2) × k」で、Cue は0.4〜1.5秒の短い音声、Answer は同じ長さで2回繰り返される。k はドリルごとに異なることがある（Unit 3.4 は 2・1・2・2・1、Unit 1.5 は 2・2・2・2・1）。Unit 1.1〜1.3 では Key の対がユニット冒頭に1組だけあり、その後に (Cue → Answer × 2) が5組続く。Unit 0.x では、タイトルの後に「Cue（0.35〜0.65秒）→ 文 × 2 → 文 × 2」がドリルの単位で、ドリル数は2または5である。

検出側にも限界がある。無音長の分布は1.0秒に谷があり、最小無音長1秒が最も安全である。しかし natural 版の一部（Unit 14.3、14.5）では Key sentence の中に1.1〜1.2秒のポーズがあり、Key が「a・b・a・b」と2つに割れる。一方、Unit 7.7、10.2、13.1 では Key の後の無音が1.2秒台しかなく、最小無音長を1.3秒に上げるとこちらが壊れる。単一のしきい値では両立しない。

## Decision

ドリルの区切りは、ターン数の割り算ではなく、セグメント列の構造から決める。解析は domain.model の DrillBook に置き、Unit とセグメント列を受け取ってドリルのリストを返す。

Turn は、番号、役割（KEY_SENTENCE、CUE、ANSWER、SENTENCE）、含まれるセグメントのインデックスのリストを持つ。通常は有音1つと続く無音1つの2セグメントだが、ポーズを含む Key sentence は有音・ポーズ・有音・無音の4セグメントになる。再生の開始位置は最初のセグメントから取る。

通常のユニットは次の規則で解析する。

1. 冒頭の2ターンは必ず Key の対とする。長さが合わなくても Key とする（タイトルが合体する場合があるため）。
2. 冒頭の2ターンの長さが合わず、1・2番目の合計と3・4番目の合計が合う場合は、ポーズで割れた Key として結合し、4ターンを2ターンにする。
3. Key の対の後は「Cue → Answer × 2」の組が続く。組の後、次の2つの有音の長さが等しければ新しいドリルの Key の対、そうでなければ同じドリルの次の Cue とする。長さの一致は0.1秒以内とする。
4. ユニット全体で Key の対が冒頭の1組しかなければ、各組を1ドリルとし、Key の対は最初のドリルに含める。
5. 解析結果のドリル数が5でなければ IrregularUnitException（UnrecoverableException を継承、グローバル経路）を投げる。

Unit 0.x（ファイル名に「Unit 0.」を含む）は次の規則で解析する。

1. 冒頭のターンはタイトルとし、ドリル0にする。役割は SENTENCE。
2. 0.8秒未満の有音を Cue とし、Cue の登場をドリルの区切りとする。Cue に続く文の役割は SENTENCE。
3. ドリル数は検証しない。

ドリル0は Unit 0.x のタイトルにだけ使う。画面のターン行は「ドリル番号-ターン番号」とし、Key sentence には「[Key]」を添える。最小無音長は1秒のままとする。

## Alternatives

### 代替案1: ターン数を5で割る

最初の実装。Unit 3.4 や 1.5 のように組の数がドリルごとに違うユニットでは、境界が実際のドリルとずれる。Unit 1.1 型では2ターン余る。採用しない。

### 代替案2: 最小無音長を1.3秒に上げて Key の分割を防ぐ

Unit 14.3、14.5 は直るが、Unit 7.7、10.2、13.1 の Key 後の無音（1.2秒台）が吸収されてターンが消える。分布に谷がある1.0秒を動かす根拠がない。採用しない。

### 代替案3: ドリル番号をやめ、ターンを通し番号で並べる

最も単純で、再生には支障がない。しかし本はドリル単位で構成されており、「ドリル3をやり直す」といった学習者の操作と対応しなくなる。完了チェックや苦手チェックの単位にも使えない。採用しない。

### 代替案4: ユニットごとの構成を設定ファイルに手で書く

確実だが、253ファイル分の記述が必要で、教材を追加するたびに手作業になる。構造は音声から読み取れるので採用しない。

### 代替案5: 通常のユニットでも Cue を長さだけで判定する

Unit 10.2 では Key（0.71秒）が Cue（0.93〜1.48秒）より短く、長さだけでは区別できない。Key の対の「長さが等しい」という性質と、Cue の後に Answer が2回来るという順序で判定する方が確実である。Unit 0.x は Key の対がないので、長さで判定する。

## Confidence Level

通常のユニットの規則についての確信度は高い。Unit 1.1、1.5、3.3、3.4、6.9、14.3、14.5、19.4 の並びを目で確認し、253ファイルのターン数の集計（5で割り切れる211、2余る24、その他3）とも整合する。

Key の結合規則と Unit 0.x の Cue のしきい値（0.8秒）についての確信度は中程度。該当例が少ない（結合は2ユニット、Unit 0.x は4ファイルを確認）。

次の場合にこの決定を見直す。実際の音声フォルダ全体を解析するテストで例外が出るユニットが見つかったとき。英語のハノン以外の教材を扱うとき。長さの一致（0.1秒）や Cue のしきい値の調整だけでは直らない並びが見つかったとき。

## Consequences

良い結果。測定したすべてのユニットで、本のドリル番号と一致する区切りが得られる。組の数がドリルごとに違っても正しく分けられる。ターンに役割が付くので、「Cue だけ聞いて答える」のような練習機能に将来つなげられる。

悪い結果。長さの一致（0.1秒）と Cue のしきい値（0.8秒）に依存する推定であり、想定外の並びでは誤った境界になる。解析コードは割り算より複雑になる。教材のばらつきは全ファイルを解析するテストで確かめる必要があり、そのテストは開発機の音声フォルダに依存する（システムプロパティで指定し、未指定ならスキップする）。

中立な結果。Turn はセグメントのインデックスのリストを持つ。以前の「有音1つ・無音1つ」の固定の形より一般的になる。Unit 0.x と通常のユニットで別の規則を使うので、ユニットの種別判定（ファイル名）が DrillBook の入力になる。
